# 漢字姓名とカタカナ姓名の二値分類アルゴリズム

この文書では、[`dataset_j.ipynb`](./dataset_j.ipynb)で分類データを作り、[`training_j.ipynb`](./training_j.ipynb)でTransformer分類器を学習・評価してTorchScriptへ出力する流れを、実装に沿って説明する。

入力は `漢字姓名_カタカナ姓名` という1本の文字列であり、出力は「正しい組み合わせ (TRUE=1)」か「誤った組み合わせ (FALSE=0)」かの2クラスである。読みを生成するモデルではなく、与えられた姓名ペア全体を判定する。

## 全体の処理

1. 名前辞書から漢字等の表記とカタカナ読みの正例を抽出する。
2. 正例の読みを変形し、複数の難易度の負例を作る。
3. 入力文字列を文字単位のID系列へ変換し、Transformer Encoderに入力する。
4. 固定負例と学習時に追加するhard negativeを使って2クラス交差エントロピーを最小化する。
5. 検証・テストで損失と正解率を測り、チェックポイントとTorchScriptモデルを保存する。

## 1. データセットの作成

### 1.1 正例の抽出と分割

`dataset_j.ipynb`は、信頼辞書 `reliable`、非信頼辞書 `unreliable`、単漢字辞書 `tankanji` からペアを抽出する。表記側は半角アルファベットを大文字・全角化し、数字も全角化する。カタカナ側は複数の長音記号を `ー` に統一し、濁点の分解表記を合成済み文字に置き換える。

実装の選別条件には注意が必要である。`select_japan` は表記側が全角アルファベットだけで構成される場合に除外するが、「漢字のみ」を必須条件にはしていない。したがって、漢字とアルファベットが混在する表記や数字・記号を含む表記など、全角アルファベットだけではない辞書キーも対象になり得る。読み側は `^[ァ-ヶー\s]+$` に合うカタカナ・長音・空白だけの文字列を採用する。

信頼辞書と非信頼辞書のペアを連結し、完全一致の重複を集合化で除いた後にシャッフルする。通常のペアを概ね訓練80%、検証10%、テスト残りに分け、単漢字辞書から選んだペアは訓練データにだけ追加する。分割境界は `siz // 10 * 8` と `siz // 10` で計算されるため、データ件数によって比率は厳密な80:10:10にはならない。

すべての既知正例は `okdic` に登録される。信頼・非信頼辞書、訓練・検証・テスト、単漢字の正例を含め、負例候補が既知正例と一致した場合に負例から除外するための集合である。

### 1.2 負例の生成

負例では漢字等の表記を変えず、カタカナ側だけを変える。`NegativeSampler` は次の難易度の候補を生成する。

| 種類 | 候補の作り方 |
|---|---|
| Easy | 正例と同じ長さのランダムなカタカナ列 |
| Medium | 長さを1文字増減させたランダムなカタカナ列。最小長は1 |
| Hard | 読みの1文字をランダムに置換 |
| Very hard | 濁点・半濁点、拗音・小書き文字などを1文字だけ変更。該当しない場合はランダム置換 |

生成された読みが元の読みと同じ、既知の正解ペア、または同一データセット内の既存ペアなら除外する。負例は辞書に追加されるため、同じ負例が重複生成された場合は1件にまとまる。

各難易度の比率は `[0.25, 0.25, 0.25, 0.25]` である。ただしコードでは `int(weight * 5)` により各難易度の試行回数が1回となり、各試行も50%の確率でスキップされる。そのため、除外・重複処理前の負例数の期待値は正例1件あたり約2件であり、コメントにある「正例と同数」には固定されない。実際のクラス比率は候補の除外や重複にも左右される。

生成後、検証データとテストデータから訓練データと同一のペアを除く。一方、テストデータを作る最終処理では検証データとの重複を除外しないため、負例生成によって検証・テスト間に同じペアが残る可能性がある。

### 1.3 保存形式と実際の学習データ

出力はgzip圧縮CSVであり、列は `kanji_kana,flag`、ペアは `漢字_カタカナ`、ラベルは `1=正例 / 0=負例` である。`kanji_kana` はアルファベット版と共通の列名である。

学習ノートブックには、複数ペアを空白で連結するデータ拡張関数と、空白をランダムに削除する関数が定義されている。しかし現在の実行セルではどちらも呼び出されず、`train_dataset_org`、`valid_dataset_org`、`test_dataset_org`をそのまま利用する。したがって、連結拡張や空白除去は現行の学習データには適用されない。

データの保存先も一致していない。生成ノートブックは `dataset3/dataset_j.<version>` を出力先に設定し、学習ノートブックは `dataset/dataset_j.<version>` から読み込む。両者が別の場所を指す実行環境では、学習前にCSVをコピーするか設定を揃える必要がある。

## 2. 文字列の符号化

### 正規化と語彙

学習時の `encode` はペアを `_` で分割し、漢字等の側とカタカナ側をそれぞれ大文字化・全角化する。長音記号と濁点付きカタカナの表記も正規化してからIDへ変換する。

文字語彙は訓練CSVに含まれる表記・読みを走査して文字単位で作る。予約IDは次のとおりである。

| ID | トークン | 用途 |
|---:|---|---|
| 0 | `<pad>` | 固定長にするためのpadding |
| 1 | `<unk>` | 語彙にない文字 |
| 2 | `<bos>` | 系列の開始 |
| 3 | `<eos>` | 系列の終了 |
| 4 | `<sep>` | 表記と読みの境界 |

このほか、実装は `●`、`＿`、`휀` を語彙から除外する。未知の漢字や記号が検証・テストデータに現れた場合は `<unk>` に変換する。

例として、`山田_ヤマダ` は概ね次の文字系列となる。

```text
<bos> 山 田 <sep> ヤ マ ダ <eos> <pad> ...
```

系列は `max_len=100` に揃える。長い入力は末尾を切り詰めてから `<eos>` を付加するため、長すぎるペアでは読みの末尾が失われる可能性がある。

## 3. Transformer分類器

### 3.1 Encoderとプーリング

分類器はDecoderを持たないTransformer Encoderである。処理は次のとおりである。

1. 文字IDを256次元のEmbeddingへ変換する。
2. 正弦・余弦の位置エンコーディングを加え、Dropoutを適用する。
3. Encoder 4層の自己Attentionで、表記と読みの全位置間の関係を計算する。
4. padding位置を除外して、隠れ状態を平均プーリングする。
5. Layer Normalizationの後、MLPから2クラスのlogitを出力する。

paddingでない位置の集合を $V$、各位置の隠れ状態を $h_i$ とすると、平均表現は次のとおりである。

$$
h_{mean} = \frac{1}{|V|}\sum_{i \in V} h_i
$$

`<bos>`、`<sep>`、`<eos>` はpaddingではないため平均に含まれる。Encoderでは `<pad>` の位置をkey padding maskで無視する。分類タスクであるため、系列の未来位置を遮断する因果マスクは使わない。

### 3.2 Attentionと出力層

自己Attentionは各文字位置が他の位置を参照する重みを計算する。基本式は次のとおりである。

$$
\mathrm{Attention}(Q,K,V) =
\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V
$$

$M$ はpadding位置を隠すマスクである。既定値は `d_model=256`、`nhead=4`、`num_layers=4`、`dropout=0.1` である。分類ヘッドは `Linear(256, 256) -> GELU -> Dropout -> Linear(256, 2)` であり、2クラスのlogitを出力する。softmaxを適用した値がTRUE/FALSEの確率となる。

## 4. 学習目的とhard-negative mining

### 4.1 分類損失

正しい組み合わせにラベル1、誤った組み合わせにラベル0を付け、Cross Entropy Lossで学習する。logitを $z_0,z_1$、正解クラスを $y$ とすると、1例の損失は次のとおりである。

$$
\ell(z,y) = -\log\frac{\exp(z_y)}{\exp(z_0)+\exp(z_1)}
$$

バッチ損失を逆伝播して勾配を求め、Adamでパラメーターを更新する。オプティマイザーにはweight decay `1e-4` を設定し、更新前に勾配ノルムを `0.5` 以下へクリップする。

### 4.2 学習時のhard negative

`use_hard_negative=True` の場合、学習バッチ内の各正例から追加負例を作る。これは一般的なGANのように生成器と識別器を競合させる学習ではない。ランダム規則で作った候補を現在の分類器で採点し、紛らわしい候補を選ぶオンラインhard-negative miningである。

候補の生成は、読みの長さに応じた訓練正例プールからの選択、長さを増減させたランダム列、読み長と漢字名長から決めた範囲でのランダム列または訓練読みの選択で行う。確率は次のとおりである。

| 確率 | 候補の選び方 |
|---:|---|
| 0.3 | 同じ長さの訓練読みから選ぶ |
| 0.1 | 元の読みより1文字長いランダム列 |
| 0.1 | 元の読みより1文字短いランダム列 |
| 0.1 | 漢字名長と元の読み長の2倍の間から長さを決め、ランダム生成 |
| 0.4 | 同じ範囲から長さを決め、その長さの訓練読みを選ぶ |

各正例から最大 `hardK=4` 個の候補を作り、モデルがTRUEと判定する確率が最も高い候補を1件選ぶ。

$$
c^* = \underset{c \in C}{\arg\max}\;
p_\theta(\mathrm{TRUE}\mid \text{kanji\_name\_}c)
$$

候補の採点中は評価モードかつ勾配計算なしとし、選ばれた候補にFALSEラベルを付けて通常のCross Entropy Lossに加える。元の読みと一致する候補は通常の選択過程で除外されるが、候補が空の場合のフォールバックでは同一読みかを再確認しない。そのため、まれに正例と同じペアがFALSEとして追加される可能性がある。

訓練時は固定負例に加えて正例1件ごとにhard negativeを1件追加する。検証・テスト時はhard negativeを追加せず、保存済みの正例・負例だけで評価する。したがって訓練と検証の損失・精度は異なる負例構成に基づく。

## 5. 学習率、検証、チェックポイント

既定値は最大100 epoch、バッチサイズ64、Adamの基準学習率 `3e-4` である。最初の10 epochは線形warmupを行い、その後は余弦減衰を適用する。

$$
\mathrm{lr}(e) = \mathrm{lr}_{base}\,m(e),\qquad
m(e)=\begin{cases}
\frac{e+1}{W}, & e < W \\
\frac{1+\cos(\pi t)}{2}, & e \ge W
\end{cases}
$$

ここで $W$ はwarmup epoch数、$t=(e-W)/(E-W)$、$E$ は総epoch数である。検証損失と訓練損失を別々のEarlyStoppingインスタンスで追跡し、`min_delta=1e-4` 以上の改善を判定する。**`best.pth` は同一epochで訓練損失と検証損失の両方が改善した場合にだけ保存**する。停止条件も両方のEarlyStoppingが停止状態になることである。

各epochのチェックポイントは `checkpoint.pth` に保存する。学習関数は再開に対応しているが、呼び出しセルは `best.pth` が存在しない場合にだけ学習関数を実行する。`best.pth` がすでにあると、そのセルからは再開処理も実行されない。

## 6. 評価とTorchScript出力

予測クラスは2つのlogitのargmaxで決める。検証・テストではCross Entropy Lossと正解率を計算し、分析セルでは正誤別に予測確率を分けてヒストグラムで確認する。

最良チェックポイントからモデルを復元し、CPU上でTorchScript traceとfreezeを行い、`.pt` として保存する。文字ID辞書とモデル設定もJSONに出力する。TorchScriptモデルの入力は文字列ではなく、正規化してID化・paddingした整数テンソルであるため、推論側でも学習時と同じ前処理が必要である。学習時の最大長は100だが、出力セルでは `max_len=20` を設定する。

## 実装上の補足

- データ拡張関数 `make_flaged_dataset` のラベル計算は `sum(flags) == len(flag)` である。CSVから読んだ `flag` は通常1文字なので、複数サンプルを結合した場合、全件正例ではなく正例がちょうど1件のときに正例ラベルとなる。ただし現在のノートブックではこの関数を呼び出していない。
- `TRAIN_YOMI` を作るセルはCSVヘッダーを除外せずに読み込むが、この辞書は後続の学習処理で使われない。
- `consistency_loss`、連結データ拡張、空白ランダム削除は定義されているが、現行の学習データ生成・学習ループでは使われない。
- 集合からリストを作ってシャッフルするため、乱数seedを固定してもPythonのhash seed等の実行環境によりデータ分割順が変わる場合がある。
- 生成ノートブックと学習ノートブックでデータディレクトリが異なる場合、学習前にCSVの配置と読み込み先を揃える必要がある。
