# `train_adv_gan_with_valid` のアルゴリズム解説

この文書では [`training_j.ipynb`](./training_j.ipynb)及び  [`training_e.ipynb`](./training_e.ipynb)に定義されている `train_adv_gan_with_valid` と、それが学習中に使うバッチ構築処理を説明します。入力は `漢字姓名_カタカナ姓名` 形式の名前ペアと正解ラベルで、ラベルは `1 = TRUE（正しい組み合わせ）`、`0 = FALSE（誤った組み合わせ）` です。

## 概要

1. モデルとAdamオプティマイザーを準備し、必要ならチェックポイントから再開する。
2. エポックごとに学習率を設定する。
3. 学習バッチの正例から誤ったカタカナ候補を複数作り、現在のモデルが最も正例らしいと判定した候補をhard negativeとして選ぶ。
4. 元の正例・負例とhard negativeをまとめ、分類誤差を逆伝播してモデルを更新する。
5. 生成負例を追加しない検証データで損失と正解率を測る。
6. ログとチェックポイントを保存し、損失の改善状況に応じて最良モデルの保存や早期終了を判断する。

## 関数について

この関数は生成器と識別器を競わせる一般的なGANの学習ではありません。負例はルールに従ってランダムに作られ、その候補の中から現在の分類モデルを使って「正例と誤認しやすいもの」を選びます。候補の選択時は `torch.no_grad()` を使っており、生成処理にも選択処理にも勾配は流れません。選ばれた負例を通常の教師あり分類データとして加える、オンラインhard-negative miningの方式です。

## モデルに渡すデータとラベル

### 文字列のエンコード

`encode` は名前ペアを `_` で分割し、各側を正規化してから、文字IDの列に変換します。区切りの `_` は `<sep>`、辞書にない文字は `<unk>` に置換します。列の先頭に `<bos>`、末尾に `<eos>` を付け、`max_len` に合わせて切り詰め・ゼロ埋めします。既定の `max_len` は100です。

### バッチのラベル付け

`build_adv_batch_flagged` は元バッチを正例 (`flag == 1`) と既存負例 (`flag == 0`) に分けます。

- 正例の入力には `TRUE` (= 1) を付ける。
- 元からある負例には `FALSE` (= 0) を付ける。
- 学習時にhard negativeを追加する設定なら、各正例から作ったhard negativeにも `FALSE` を付ける。

その後、それぞれの入力列とラベル列を連結してモデルに渡します。あるバッチに正例が `P` 件、既存負例が `N` 件あれば、hard-negative有効時のバッチ件数は原則として `2P + N` 件です。正例1件ごとに選ばれたhard negativeが1件加わるためです。

## Hard negativeの生成と選択

### 負例候補を作る

`TRAIN_KANA` は学習CSVから正例のカタカナを読み込み、文字列長ごとの候補プールを作ったものです。`generate_negatives` は正例の読み `kana` と漢字 `kanji` に対して、次のいずれかの方法で誤った読み候補を作ります。

| 確率 | 候補の作り方 |
|---:|---|
| 0.3 | 同じ文字数のカタカナを学習データのプールから選ぶ |
| 0.1 | 正例より1文字長いランダムなカタカナを作る |
| 0.1 | 正例より1文字短いランダムなカタカナを作る（最小長は1） |
| 0.1 | 漢字姓名の長さと正例の読みの2倍の長さの間から長さを選び、ランダムなカタカナを作る |
| 0.4 | 同じ範囲から長さを選び、その長さのカタカナを学習データのプールから選ぶ |

ランダム文字列の先頭文字には語頭用のカタカナ集合を使い、残りには小書き文字・促音・長音などを含む集合を使います。候補が元の正例の読みと同一でないことを確認し、最大10回試します。候補が得られない場合は、同じ長さのプールからの選択、またはランダム生成にフォールバックします。

### 現在のモデルで最も紛らわしい候補を選ぶ

`make_hard_negatives_batch` は正例1件につき `K` 個の候補を生成します。既定値は `hardK = 4` です。各候補は元の漢字姓名と候補の読みを組み合わせた文字列になります。

候補 \(i\) に対してモデルが出す2クラスのlogitを \(z_{i,0}\)（FALSE）、\(z_{i,1}\)（TRUE）とすると、TRUEの確率はsoftmaxで

\[
p_i(\mathrm{TRUE}) =
\frac{\exp(z_{i,1})}
{\exp(z_{i,0}) + \exp(z_{i,1})}
\]

と計算されます。正例ごとに、この確率が最大の候補を選びます。

\[
\mathrm{hard}(k,a) =
\underset{c \in C(k,a)}{\arg\max}\;
p_\theta(\mathrm{TRUE} \mid k\_c)
\]

ここで \(k\) は漢字姓名、\(a\) は元の正しい読み、\(C(k,a)\) は生成された候補の集合です。つまり、現在のモデルが最も「正しい組み合わせらしい」と誤認する負例を選んでいます。候補評価中はモデルを評価モード・勾配計算なしにし、もともと学習モードだった場合は学習モードに戻します。

通常は候補が元の読みと異なるよう生成時に試しますが、候補を10回作っても得られない場合のフォールバック、および候補リストが空になった場合のフォールバックでは、元の読みと同一でないことを再確認しません。そのため、極端なデータ条件では正例と同じ読みが負例ラベルで追加される可能性があります。

### 学習バッチに追加する

選ばれた文字列には `FALSE` (= 0) を割り当てます。したがって、モデルには「正しい読みはTRUEに、既存の誤った組み合わせと、正例から作った紛らわしい読みはFALSEに分類する」よう学習させます。

hard negativeは各学習バッチの現在のモデルで選び直されます。モデルが更新されるにつれて誤認しやすい候補も変わるため、固定の負例だけを繰り返すのではなく、学習状況に応じて難しい負例を追加できます。`use_hard_negative=False` にするとこの追加を無効化できます。ノートブックの既定値は `True` です。

## 1学習バッチでのパラメーター更新

1. `model.train()` にして学習モードに切り替える。
2. 元の文字列バッチを `build_adv_batch_flagged` に渡し、正例・既存負例・hard negativeを作る。
3. モデルが各入力について2クラスのlogitを出力する。
4. `CrossEntropyLoss` で正解ラベルとの損失を計算する。
5. 損失を逆伝播して勾配を計算する。
6. `grad_clip` が `None` でなければ勾配ノルムを指定値以下にクリップする。
7. Adamオプティマイザーでモデルのパラメーターを更新する。

クラス \(c \in \{0,1\}\) のlogitを \(z_c\)、正解クラスを \(y\) とすると、1サンプルの交差エントロピー損失は

\[
\ell(z,y) = -\log
\left(
\frac{\exp(z_y)}{\exp(z_0)+\exp(z_1)}
\right)
\]

です。バッチ全体では、追加したhard negativeも含む各サンプルの損失を平均します。誤ったクラスに高い確率を割り当てるほど損失は大きくなり、勾配更新によって正解クラスの確率を高める方向へモデルが調整されます。

既定の主な設定は次のとおりです。

| 設定 | 既定値 | 意味 |
|---|---:|---|
| `epochs` | 100 | 最大エポック数 |
| `batch_size` | 64 | 元データローダーのバッチサイズ。hard negative追加後の実際の件数は正例数に応じて増える |
| `hardK` | 4 | 正例1件につき生成して比較する負例候補数 |
| `lr` | 0.0003 | Adamの基準学習率 |
| `grad_clip` | 0.5 | 勾配ノルムのクリップ値 |
| `patience` | 5 | 早期終了判定に使う連続未改善エポック数 |
| `min_delta` | 0.0001 | 損失改善とみなす最小幅 |

モデルがNaNまたは無限大のlogitを出したバッチ、または損失がNaN/無限大になったバッチはメッセージを表示して更新をスキップします。学習損失と正解率は、オプティマイザー更新前にそのバッチで計算したlogitから集計します。

## 学習率スケジュール

エポックごとに基準学習率 `lr` に倍率を掛け、その値をオプティマイザーに設定します。

### Warmup

最初の `warmup_epochs` エポックでは、倍率を線形に増加させます。

\[
m(e) = \frac{e+1}{\text{warmup\_epochs}}
\quad (e < \text{warmup\_epochs})
\]

既定の `warmup_epochs = 10` では、最初のエポックは `lr` の10分の1、10エポック目は `lr` になります。

### Cosine decay

Warmup終了後、`use_cosine=True` の場合は余弦関数に従って学習率を下げます。

\[
t = \frac{e-\text{warmup\_epochs}}
{\max(1,\text{epochs}-\text{warmup\_epochs})},
\qquad
m(e) = \frac{1+\cos(\pi t)}{2}
\]

実際の学習率は `lr * m(e)` です。コサイン減衰を無効にした場合、Warmup後の倍率は1のままです。

## エポック終了時の検証

学習エポックが終わると `model.eval()` に切り替え、`torch.no_grad()` のもとで検証データを処理します。このとき `build_adv_batch_flagged(..., add_hard=False)` とするため、検証はデータセットにあらかじめ付いている正例・負例だけで行い、学習時に動的生成したhard negativeは追加しません。

検証損失はバッチ損失をサンプル数で重み付けして合計し、処理した全サンプル数で割ります。正解率は、予測クラス `argmax(logits)` と正解ラベルが一致した件数を全件数で割ります。学習損失・正解率も同様に集計されますが、学習側の値にはhard negativeが含まれます。そのため学習と検証の指標は、完全に同じデータ構成で計算されたものではありません。

## Early stoppingと最良モデルの保存

`EarlyStopping` を2つ作り、一方は検証損失、もう一方は学習損失を追跡します。それぞれ独立に、現在の損失が

\[
\text{best\_loss} - \text{min\_delta}
\]

より小さければ改善とし、最良損失を更新して未改善カウンターを0に戻します。それ以外ではカウンターを1増やします。カウンターが `patience` に達すると、そのEarlyStoppingインスタンスの `should_stop` が `True` になります。

各エポックで学習損失と検証損失の両方を判定した後、**同じエポックで両方が改善した場合に限って** `best.pth` を保存します。これは「検証損失だけが改善したときに最良モデルを保存する」一般的な条件とは異なります。学習損失と検証損失の改善タイミングがずれると、検証損失が改善していてもそのエポックのモデルは `best.pth` に保存されない場合があります。

また、停止条件も両方の `should_stop` が `True` になることです。片方だけが `patience` 回未改善でも、その時点では停止しません。2つの損失の未改善回数が別々に数えられ、それぞれが閾値に達したときに終了します。実装では損失が後から改善しても `should_stop` を `False` に戻さないため、このフラグは一度 `True` になるとそのままです。したがって、片方がいったん停止条件に達した後、もう片方も条件に達した時点で終了します。

## チェックポイントと再開

各エポックで `checkpoint.pth` に次の情報を保存します。

- モデル構造を復元する設定（文字ID辞書、埋め込み次元、最大長、head数、層数、dropout）
- エポック番号
- モデルの重み
- Adamオプティマイザーの状態
- 検証損失・学習損失の最良値

呼び出し側では `resume=True` が指定されているため、`checkpoint.pth` があればモデルとAdamの状態を読み込み、通常は保存エポックの次から再開します。`resume_restart=True` の場合は重みとオプティマイザー状態を復元しつつ、エポック番号は0から始めます。

再開時には最良損失値は読み戻されますが、EarlyStoppingの未改善カウンター (`counter`) や停止フラグはチェックポイントに保存されていません。したがって、再開後の未改善回数は初期状態から数え直されます。

なお、通常チェックポイントの保存は当該エポックのEarlyStopping判定より前です。このため、`checkpoint.pth` に書かれる最良損失値はそのエポックの判定前の値です。一方、`best.pth` は両損失の改善判定後に保存されます。

## ログ

TensorBoardのログディレクトリに、エポック単位で次の値を書き込みます。

- `train/loss`, `train/acc`
- `valid/loss`, `valid/acc`
- `lr`
- `hardK`

加えて標準出力にもエポック番号、学習・検証損失、正解率、学習率、`hardK` を表示します。

## ノートブックから呼び出すときの注意

このノートブックでは、`best.pth` が存在しない場合にだけ学習関数を呼び出します。したがって、すでに `best.pth` がある状態でセルを実行すると、この関数自体は呼び出されず、チェックポイント再開処理も実行されません。学習関数内の再開機能を使うには、呼び出し側の条件も確認してください。

また、関数内で `args = locals()` を作っていますが、その値は後続処理で参照されていません。`consistency_loss` も別途定義されていますが、この学習関数の損失計算では使用されず、ここで最適化されるのは `CrossEntropyLoss` のみです。
